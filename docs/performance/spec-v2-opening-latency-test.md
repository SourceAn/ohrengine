# OhEngine 打开延迟测试规程 v2

版本 v2.0 ｜ 2026-10-09 ｜ 适用格式：EPUB、TXT、CBZ/CBR ｜ 基线文档：《OhEngine 打开延迟审计报告（真实用户路径·真机）20261009》

## 0. 目的、范围与原则

**目的**：在 v1 审计的基础上，补齐方法缺口（口径不一、样本过少、冷热状态不严、缺少异常与交互场景），产出可复现、可回归、可对外下结论的测试规程。

**范围**：进入 App 后「打开一本书」的全过程，包括首帧、进度恢复、打开后的首批交互、缓存一致性、中断恢复、资源占用、异常输入。冷启动（App 启动本身）不在判定范围，但需记录。

**七条原则**

1. 口径统一：所有对外结论只用 T\_total（点击 → 首帧上屏），分段指标仅用于归因。
2. 可复现：每条数据附 run\_id、设备、build、语料、状态、入口，能被他人重跑。
3. 信状态不信日志：是否重新解压/重建索引以文件系统状态（inode、mtime、文件列表、大小）判定，日志只作辅证。
4. 先证伪再证明：每个「达标」结论必须经过至少一轮针对性的破坏性场景（中断、替换、损坏）。
5. 无效批次作废，不补推算值；窗口内未完成的场景标注「未完成」。
6. 先修埋点再修性能：埋点失效期间不出具任何「达标」结论。
7. 以 P95 判定，不以平均数判定。

## 1. 通用规范（三类格式共用）

### 1.1 计时口径

| 指标 | 起点 | 终点 | 用途 |
| --- | --- | --- | --- |
| **T\_total** | 点击事件注入时刻 | 首帧真实上屏 | **唯一对外结论指标** |
| T\_launch | 点击 | ABILITY\_CREATE | 归因 |
| T\_shelf | ABILITY\_CREATE | SHELF\_CONSUME | 归因 |
| T\_prep | SHELF\_CONSUME | SESSION\_INIT\_START | 解压/拷贝/导入 |
| T\_parse | SESSION\_INIT\_START | 解析完成（OPF/索引头/图片目录） | 归因 |
| T\_layout | 解析完成 | 首屏排版完成 | 归因 |
| T\_render | 排版完成 | FIRST\_FRAME | 归因 |
| T\_restore | 打开 | 阅读位置恢复完成 | 有书签/进度时必测 |

硬性规定：

- 任何报告表格若起点不是「点击」，必须在列名中写明起点（v1 中 EPUB/TXT 表从 SESSION\_INIT\_START 起算，与 CBZ 表口径不一致，v2 禁止）。
- 所有时间取设备侧 hilog 时间戳差值，不使用主机时钟。
- 首帧定义：用户可见的第一页正文/图片已绘制并提交显示。不得仅凭 FIRST\_FRAME 日志认定，见下条校验。

**首帧交叉验证**：每个格式至少抽 10% 的运行，用 hitrace（render/vsync 相关事件）或 60fps 录屏逐帧，核对 FIRST\_FRAME 日志与真实上屏的偏差。偏差 > 16.7 ms（一帧）则必须修正埋点位置，并在报告中写明修正量。

### 1.2 前置阻塞项：埋点与门禁

以下条件未满足前，不得进入正式测试：

1. 修复 `openMs`、`restoreMs`（v1 中恒为 0）。
2. 每条埋点输出统一字段：run\_id、format、corpus\_id、state（L0–L3）、entry（shelf / external）、pid、exit 方式、时间戳。
3. 埋点自身开销检验：开启/关闭埋点各跑 20 次，T\_total 中位数差 < 3 ms。
4. 提供一个一键脚本从 hilog 解析出 CSV（字段见 1.9），解析规则对 `THREAD_BLOCK` 等关键字必须限定在应用进程 pid 内（v1 曾误匹配系统 `sceneboard` 日志）。

### 1.3 设备矩阵

| 编号 | 设备 | 用途 | 是否必选 |
| --- | --- | --- | --- |
| D1 | HUAWEI Mate 70 Pro+（已有） | 旗舰基线 | 必选 |
| D2 | 中端真机（内存 ≤ 8 GB，闪存规格较低） | 暴露 IO 与内存问题 | **必选** |
| D3 | 低存储状态设备（剩余空间 < 10%，可用 D1/D2 填充） | 磁盘满、配额、解压失败 | 建议 |
| D4 | DevEco 模拟器 | 仅做功能回归，不出性能结论 | 可选 |

每份报告头部必须记录：型号、系统版本号、API 级别、App build hash、存储总量与剩余、电量、电池温度、性能模式、亮度。

### 1.4 环境控制

- 全程固定：亮度 50%、关闭自动亮度、关闭省电模式、性能模式保持系统默认、屏幕常亮。
- 飞行模式 + 关闭 Wi-Fi/蓝牙，关闭自动更新与云同步，排除网络与后台同步干扰。
- 供电方式统一（建议 USB 供电），并另做一轮不插电抽样，记录两者差异。
- 电量 ≥ 60%；电池温度在 28–36 ℃ 区间才开始一轮，超出则静置降温后再测（读取方式用 DevEco/SmartPerf 或系统温度节点，须在报告中写明）。
- 每轮开始前：清空最近任务，重启设备后空闲 5 分钟，关闭其它所有第三方应用。
- 相邻两次运行间隔 ≥ 30 s；连续 N 次的数据按时间序列检查是否有单调变慢（热降频迹象）。
- 运行顺序随机化或 ABBA 交替，避免热累积造成系统性偏置。

### 1.5 状态分级（冷热定义）

| 状态 | 定义 | 准备方法 |
| --- | --- | --- |
| **L0** 同进程热 | 进程存活，返回书架后再点同一本书 | 打开→返回键→等待 3 s→再点 |
| **L1** 进程冷 | 进程已退出，磁盘产物（解压目录/索引/缓存）仍在 | 退出后确认进程消失，再启动并点击 |
| **L2** 深度冷 | 进程已退出，该书全部产物被清除，页缓存被排空 | 见下 |
| **L3** 设备冷 | 重启设备后空闲 5 分钟的首次打开 | 重启，不预热 |

**L2 准备清单**（以该书为单位）：`books/<书名>_extracted`、`cache/books` 下该书条目、索引文件、`reading_state`、`checkpoint.json`、`.tmp` 残留，全部删除，并用 `ls` 核对为空。

**页缓存处理**：若设备允许（userdebug/root），L2 前执行 `sync` 并写 `drop_caches`；否则在 L2 前顺序读取一个大于设备内存 1.5 倍的无关文件把页缓存挤出。报告必须写明采用了哪种方式。v1 只清 `cache/` 与解压目录，未处理页缓存，L2 数据偏乐观。

**退出方式**必须分别覆盖并标注 exit 字段：`kill`（`aa force-stop`）与 `back`（返回键正常退出，等待进程自然结束）。

### 1.6 行前 / 行后校验（每次运行都执行）

**行前**（任一失败则本次不执行）：

1. `uitest dumpLayout` 含「书架」，且目标书在可视区域，点击坐标由当次 dumpLayout 解析得到，不复用旧坐标。
2. 以文件系统核对状态是否符合 L0–L3 的定义（产物是否存在、inode 记录、文件数、大小）。
3. 记录磁盘剩余、电池温度、内存可用量。
4. 无 `.tmp` 残留（除非该场景专测残留）。

**行后**（任一失败则本次作废并记录原因）：

1. 日志含 `OPEN_TOTAL page=… total=N`，且 total 与语料清单中的已知值一致。
2. `dumpLayout` 含阅读页元素；截图的首页与语料基准截图对比一致（哈希或 SSIM ≥ 0.98）。
3. 应用进程无 crash、ANR、`THREAD_BLOCK`（faultlog 与 hilog 双查，限定 pid）。
4. 再次记录产物状态（inode、文件数、大小），与行前对比，判定是否发生了重解压/重建索引。

### 1.7 样本量与统计

- 每个「设备 × 语料 × 状态 × 入口」组合：L0/L1 ≥ 20 次（丢弃前 2 次预热）；L2 ≥ 10 次；L3 ≥ 5 次（不预热）。
- 报告 min / P50 / P90 / P95 / max / 标准差。**判定以 P95 为准**。
- 不剔除离群值，只标注并解释；P95/P50 > 2 必须附原因调查。
- 修复前后对比必须在同一批次内交替运行（A/B/A/B），不得拿不同日期的数据比较。
- 变化被认定为有效的条件：相对变化 > 10% 且 > 2 倍标准差。
- 窗口内未完成的场景标注「未完成（窗口 X s）」，不得用推算值填充。

### 1.8 判定标准（暂定，须经竞品校准）

| 指标（P95） | 优质 | 可接受 | 不达标 |
| --- | --- | --- | --- |
| 首次打开 T\_total（L2/L3，文件 ≤ 50 MB） | < 500 ms | < 1 s | ≥ 1 s |
| 首次打开 T\_total（大文件，后台继续） | < 500 ms | < 800 ms | ≥ 1 s |
| 重复打开 T\_total（L0） | < 100 ms | < 300 ms | ≥ 500 ms |
| 进程冷重开 T\_total（L1） | < 300 ms | < 500 ms | ≥ 1 s |
| 点击到首个 UI 反馈（占位/进度） | < 100 ms | < 200 ms | ≥ 300 ms |

**竞品校准**：在 D1、D2 上选 2–3 个对照阅读器（系统自带阅读器、至少一款主流第三方），同一本书、同一状态，用录屏逐帧测 T\_total，各 10 次取 P50。最终阈值取 `min(本表阈值, 竞品 P50)`。校准结果写入报告附录，并说明 300/500 ms 这类经验线不是官方标准。

### 1.9 数据记录格式

CSV 字段：run\_id, date, device, build, format, corpus\_id, state, entry, exit, T\_total, T\_launch, T\_shelf, T\_prep, T\_parse, T\_layout, T\_render, T\_restore, re\_extracted(0/1), inode\_before, inode\_after, files\_before, files\_after, bytes\_after, pss\_peak\_mb, valid(0/1), invalid\_reason。

原始 hilog、dumpLayout、截图、录屏按 run\_id 归档保存，保留至该版本发布后至少 90 天。

### 1.10 通用中断与异常矩阵（各格式章节引用，编号 X1–X10）

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| X1 | 打开过程中按返回键 | 取消任务，无残留，无崩溃，书架可立即再点 |
| X2 | 在 10% / 50% / 90% 进度强杀 | 重开时能判定产物不完整并安全重建或续做，不得读到半成品 |
| X3 | 打开中切后台再回前台 | 任务继续或安全取消，回前台后状态一致 |
| X4 | 打开中旋转屏幕 / 折叠屏展开 | 不崩溃，不重复触发打开，首帧布局正确 |
| X5 | 打开中来电或通知打断 | 同 X3 |
| X6 | 磁盘空间不足（预先填满存储） | 给出明确提示，回滚已写入的临时产物，不留垃圾 |
| X7 | 系统低内存（用压测应用占用内存） | 不被杀；若被杀，重开能恢复 |
| X8 | 源文件在打开前被删除/移动/改名 | 明确错误提示，不白屏 |
| X9 | 源文件被同名替换（大小相同、内容不同，mtime 相同或不同各一组） | 缓存必须失效并重新解析，不得显示旧内容 |
| X10 | 外部 URI 权限被撤销 | 明确错误提示 |

每个 X 场景的结论格式：预期 / 实测 / 残留检查（文件、内存）/ 是否通过。

## 2. EPUB 测试规程

### 2.1 目标

1. 在 L0–L3 全部状态下，用统一口径（T\_total）给出首开与重开延迟的 P95。
2. 证明缓存/指纹/checkpoint 机制在中断、替换、升级下**正确**，而不仅是「快」。
3. 覆盖真实 EPUB 的多样性（长篇、图文、内嵌字体、固定版式、竖排），不再以单本 2.2 MB 样本推广。
4. 验证打开后首批交互（翻页、跳章、改字号、搜索）的延迟与内存。
5. 验证恶意/损坏输入被安全拒绝。

| 编号 | 描述 | 规模 | 测试目的 |
| --- | --- | --- | --- |

### 2.4 打开后交互（首批 30 秒）

每项 ≥20 次，记录 P50/P95：

| 交互 | 度量 | 暂定阈值（P95） |
| --- | --- | --- |
| 连续下一页 50 次（间隔 0 与 200 ms 两种） | 触发到新页上屏 | < 50 ms 优质，< 100 ms 可接受 |
| 目录跳章（跨 1 / 10 / 100 / 最后一章） | 点击到新章首屏 | < 300 ms |
| 字号、行距、字体切换 | 操作到重排首屏 | < 300 ms |
| 拖动进度条到 50% 与 100% | 松手到首屏 | < 300 ms |
| 全文搜索（常见词与罕见词） | 提交到首个结果 | < 500 ms；并记录全书完成耗时 |
| 夜间模式切换 | 操作到首屏 | < 200 ms |
| 图文书首张图 | 进入章节到图片可见 | < 300 ms |
| 内存 | 连续翻页 500 页的 PSS 增长 | < 10%，且无单调上涨 |

PSS 采集：`hidumper --mem <pid>` 或 DevEco Profiler，按固定间隔采样并保存曲线。

### 2.5 缓存一致性与指纹专项

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| C-E1 | 记录 `isFingerprintValid` 使用的要素（大小、mtime、内容哈希）及对 E4 的计算耗时 | 耗时计入 T\_prep；若为全量哈希需评估是否阻塞首帧 |
| C-E2 | 修改内容但保持大小不变（mtime 变与不变各一组） | 缓存失效并重新解析，不显示旧内容 |
| C-E3 | 只改 mtime，不改内容 | 记录实际行为并与设计文档对照 |
| C-E4 | 同一本书复制到另一路径后打开 | 产物不冲突，行为与设计一致 |
| C-E5 | 两本同名不同内容的书（不同目录） | 解压目录必须隔离，不得串书（当前目录名取自文件名，重点验证） |
| C-E6 | 分别在 UNZIP、PARSE、CACHE 阶段强杀后重开 | checkpoint 标记与实际文件一致；不一致即缺陷（v1 在 CBZ 已发现标记全完成而内容只有一半） |
| C-E7 | 强杀后检查目录名 | 正式目录名下不得出现半成品；中间态只能在 `.tmp` 名下 |
| C-E8 | 连续导入多本直至超配额 | 解压产物受配额管理，按 LRU 淘汰；被淘汰的书可重新打开并重建 |
| C-E9 | 删除书籍后检查产物 | 解压目录、索引、阅读进度按设计清理，无孤儿文件 |

以上均用 inode、文件数、字节数、`.tmp` 是否存在判定，不以日志为准。

### 2.6 分段归因与剖析

- 对每本语料抓 hitrace/Profiler，拆出：ZIP 中央目录读取、container 与 OPF 解析、目录（TOC）构建、首章 XHTML 解析、CSS 解析、字体加载、排版、绘制。
- **线性度**：对 E3 截取 100 / 500 / 1000 / 2000 章，绘制 T\_parse 随章节数的曲线，识别 O(n²) 行为。
- **字体**：对 E5 对比「系统字体先出首帧、自定义字体异步替换」与现状，确认内嵌字体不阻塞首帧，并检查替换时是否发生页面抖动或重排。
- **图片**：对 E4 记录首屏图片的解码线程与耗时，确认图片解码不在主线程。
- **IO**：对比 L2 与 L1 的 T\_prep，估算磁盘读取占比。

### 2.7 判定

**性能通过**：S-E01 至 S-E07 的 P95 满足 1.8 的阈值；re\_extracted 在 L0/L1 必须为 0；D2 上读取 E4 的 PSS 峰值 < 250 MB（暂定，须以基线校准）。

**正确性通过**：C-E1 至 C-E9 全部符合预期；X1–X10 无残留、无崩溃。

**安全通过**：

- E17：必须被限流或拒绝（设置解压总量、条目数、压缩比上限），耗时 < 2 s 内给出明确错误，磁盘占用增长 < 100 MB，内存无异常暴涨。
- E18：所有条目必须落在解压目录内，不得写出目录之外；以解压前后全盘（应用沙箱内）文件差异核对。
- E15、E16、E19：给出明确错误提示或按设计容错，不白屏、不残留。

**v1 结论复核**：EPUB 75 ms / 43 ms 的原口径为 SESSION\_INIT\_START 到 OPEN\_TOTAL，须用 T\_total 重测；2.2 MB 单样本的结论须由 E1–E7 验证后才能推广。

## 3. TXT 测试规程

### 3.1 目标

1. 验证「首屏不等完整索引」：首帧 P95 < 500 ms，完整索引在后台继续并热替换。
2. 解释并量化索引吞吐异常（v1：52 MB 用 89 s，约 0.6 MB/s）。
3. 覆盖编码、换行、章节结构、字符的多样性，保证首屏文本正确。
4. 验证索引落盘的原子性与中断恢复。

### 3.5 索引构建期间的交互（完整索引未完成时）

| 操作 | 预期 |
| --- | --- |
| 立即连续翻页 50 次 | 不等待索引，响应 P95 < 100 ms |
| 立即拖动进度条到 50% / 100% | 展示估算位置并在索引完成后校正；校正后的位置偏差（字符数）要记录；不白屏，等待 < 500 ms 或有占位 |
| 立即跳到末尾 | 同上 |
| 立即搜索 | 明确提示「索引中」，或基于已索引部分返回并在完成后补全 |
| 立即改字号 / 字体 / 行距 | 取消旧任务并重启，无任务堆积，无崩溃 |
| 立即返回键退出 | 取消 TaskPool 任务；退出后 30 s 内进程 CPU 占用接近 0，无残留线程 |
| 切后台再回前台 | 记录后台期间索引是否继续；回前台后状态一致 |
| 打开目录 | 渐进显示或占位，不阻塞 |
| **热替换时刻** | 用 60 fps 录屏或截图序列比对前后 10 帧：屏幕文字不得跳动，位置偏差 = 0，闪烁次数 = 0 |

### 3.6 中断与恢复专项（T4、T5）

1. **强杀恢复**：在完整索引进度 10% / 50% / 90% 处强杀（用索引进度日志或定时触发）。重开后：首帧 P95 < 500 ms；若实现了增量落盘，应从断点续建；若未实现，应整体重建；任何情况下都不得信任半成品索引。
2. **落盘原子性**：循环强杀 100 次，时刻随机分布并覆盖落盘阶段（必要时在落盘阶段注入延迟以扩大窗口）。每次检查索引文件要么完整可用（校验和与版本头通过），要么不存在；不得出现可被加载的半成品。
3. **索引文件损坏**：分别构造截断、翻转随机字节、版本号不符、长度字段异常，重开必须检测并重建，不崩溃，不出现错位文本。
4. **磁盘满**：落盘失败时阅读继续，不崩溃，不留 `.tmp`。

### 3.7 缓存一致性

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| C-T1 | 源文件末尾追加内容（大小变） | 索引失效并重建 |
| C-T2 | 大小不变、内容改变（mtime 变与不变各一组） | 索引失效，不显示错位内容 |
| C-T3 | 手动切换编码（若支持） | 旧索引失效 |
| C-T4 | 改变字号、行距、边距、屏幕方向、折叠屏展开 | 记录索引是否与排版参数耦合；若耦合，缓存键必须包含这些参数，且不同参数的索引不得串用 |
| C-T5 | 引擎版本升级 | 旧索引不兼容时安全重建 |
| C-T6 | 两个同名不同内容的文件 | 索引不串用 |
| C-T7 | 删除书籍 | 索引、进度按设计清理，无孤儿文件 |

### 3.8 性能剖析专项（解释 0.6 MB/s）

| 步骤 | 内容 |
| --- | --- |
| P1 | 基线：只做读取加解码，测纯吞吐（预期应远高于索引吞吐，如 > 100 MB/s） |
| P2 | 逐阶段计时：读取、编码检测、解码、换行切分、章节识别、文本测量、分页、序列化；列出各阶段占比 |
| P3 | 线性度：用 TL 阶梯绘制 T\_idx\_full 与文件大小的曲线并拟合指数；若指数明显大于 1，定位二次复杂度来源 |
| P4 | 内存分配：记录 GC 次数与耗时、临时对象与字符串拼接 |
| P5 | 并行度：现为单个 TaskPool 任务时，测分块并行（按行或章边界）的加速比 |
| P6 | 章节识别：用 TC5、TC6 检查正则是否存在灾难性回溯 |
| P7 | 文本测量：统计测量调用次数，评估估算或采样的可行性 |

产出：阶段耗时占比表与瓶颈排序。暂定目标：索引吞吐 ≥ 20 MB/s（须与设计方共同确认后定稿）；对 52 MB 文件，完整索引时间随之确定。

### 3.9 判定

**性能**：T0–T5 在 L2/L3 的 T\_total P95 < 500 ms；T\_enc 在首块 ≤ 512 KB 下 < 50 ms；T6 在 1 s 内给出明确反馈；完整索引期间主线程单次最长占用 ≤ 50 ms，丢帧率不高于基线。

**正确性**：TE1–TE8 首屏文本与基准一致（乱码数 = 0）；TE9、TE10 不崩溃并按设计处理（替换符或自动回退）；TC1–TC3 章节数与基准完全一致；TU1–TU5 渲染正确；热替换偏差为 0。

**鲁棒**：TS8–TS10 有明确处理（空文件提示、二进制拒绝或降级），不白屏、不崩溃；TS5 超长单行不卡死、不 OOM。

**v1 复核**：txt-s 1692 ms、txt-m 3987 ms 等冷首帧数据按 T\_total 重测；txt-l 冷、txt-xl 热在 v1 中为「窗口内未完成」，v2 必须延长观察窗口至完成，并给出实测值。
